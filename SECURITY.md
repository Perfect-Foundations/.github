# Security Policy

Perfect Foundations contains foundational libraries that may eventually be used by correctness-sensitive systems.

For non-sensitive defects, use the relevant repository's normal issue tracker once that repository is public.

For suspected security vulnerabilities, avoid publishing exploit details in a public issue. Use GitHub's private vulnerability reporting/security-advisory workflow when it is enabled for the affected repository.

Security claims must be scoped precisely. A crate being written in Rust, tested, deterministic, or panic-free does not by itself make it cryptographically secure, safety-certified, medically certified, or suitable for any regulated use.
